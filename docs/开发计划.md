# Cool Request RabbitMQ 小工具 — 开发计划

## 一、目标与背景

为 IntelliJ 平台插件 Cool Request（2026.2 环境）开发一个 RabbitMQ 可视化小工具（Tool）。
工具以独立 JAR 形式被 Cool Request 宿主自动加载，用户在宿主「工具」页即可完成 RabbitMQ 的
连接管理、消息生产、消息消费与消息查看，无需切换外部客户端。

参考对象：

- 已安装的 `RocketMQ` 工具（`%USERPROFILE%/.config/.cool-request/request/tools/b80d55ec-...jar`，同名模板位于 `cool-request-tools/tools-rep/rocketmq/`）：验证了宿主加载协议、HostManager 持久化、生产/消费面板、MessageDetail 详情弹窗等完整范式。
- 模板 `cool-request-tools/tools-rep/tool-template/prompt.txt`：约定的包结构、工厂类、三个资源文件、IDEA UI 优先原则。

## 二、宿主加载协议（核实结论）

- 工具 JAR 根目录必须含三个资源：
  - `coolrequest.tool` — 实现 `dev.coolrequest.tool.ToolPanelFactory` 的工厂类全限定名
  - `tool.name` — 工具名（UTF-8 纯文本）
  - `logo.svg` — 48×48 圆角 SVG 图标
- 工厂类必须无参构造、实现 `ToolPanelFactory.createToolPanel()`，返回 `CoolToolPanel`。
- `CoolToolPanel` 接口（cdk `dev/coolrequest/tool/CoolToolPanel.class`）：
  - `JPanel createPanel()`、`void showTool()`、`void closeTool()`
- Project 注入：在 `CoolToolPanel` 匿名类里声明 `private Project project;` 字段，
  宿主 `ToolComponentView.autoWrite` 反射注入运行时 Project。
- 依赖打包：宿主用类加载器只从工具 JAR 加载业务类，父加载器仅兜底宿主插件主类（`ToolPanelFactory`/`CoolToolPanel`）。
  因此 **amqp-client / slf4j 等第三方依赖必须打进工具 JAR**（shadow 平铺），RocketMQ 工具即是如此（内嵌 fastjson/netty/rocketmq-client）。

## 三、技术选型

- 语言：Java 17（与宿主插件构建目标一致，参考 RocketMQ 模板 sourceCompatibility=17）。
- UI：优先 IntelliJ 平台组件（JBLabel/JBTextField/EditorTextField/JBTable/JBSplitter/DialogWrapper/ComboBox/JBScrollPane/JBUI），不用原生 Swing 布局实现交互。
- 消息客户端：`com.rabbitmq:amqp-client:5.21.0`（纯 Java、依赖 slf4j-api，二者均内嵌）。
- 持久化：`PropertiesComponent.getInstance(project)`（与 RocketMQ 工具一致，零额外状态文件）。
- 构建：Gradle 工程（规范交付物，含 intellij platform / shadow 配置）+ 轻量 `build-tool.sh`（本机 IDEA lib 编译 + 手动 shadow 打包），后者用于规避拉取 IDEA 平台不稳定、保证离线可产出成品 JAR。

## 四、功能设计（相对 RocketMQ 参考的增强点）

1. 连接管理（多连接、可编辑）
   - 字段：地址 host:port、vhost、用户名、密码；连接级持久化；下拉选择 + 新增/编辑/删除；
     选中即记忆，跨会话保留。默认提供 `guest/guest @ localhost:5672`。
2. 生产面板
   - Exchange、RoutingKey、Exchange 类型（direct/topic/fanout/headers）显式化；
   - 消息体（多行编辑器）+ 可选 Headers/PROPS 元数据（JSON，可折叠）；持久化最近输入；
   - 发送在 pooled thread 执行，结果显示 msgId/状态/耗时/异常堆栈；Exchange 支持未声明时自动声明。
3. 消费面板
   - Queue（自动声明 durable 队列以防未存在失败）、Consumer Tag 前缀、Prefetch 可选；
   - 实时表格（时间/Queue/DeliveryTag/RoutingKey/大小/Body 摘要），行数上限，清空按钮；
   - Body 多策略解码：优先 JSON、否则纯文本、再否则 hex（提升 RabbitMQ 二进制 message 可见性）；
   - 消息详情弹窗：完整元数据 + Body 解码切换（Text/JSON/Hex）+ 复制；
   - active 消费中禁止改参数，Stop 后恢复；重复启动前自动停旧消费。
4. 体验细节
   - 所有网络/阻塞操作一律 pooled thread，结果回 EDT；
   - 面板关闭（closeTool）自动关闭连接与消费器，防句柄泄漏；
   - 图标/文案与宿主已有的 RocketMQ 等工具保持一致风格。

（可选增强，首版不含：基于 Management HTTP API 的 queue/exchange 浏览；重试/死信辅助。）

## 六、实施步骤

1. 初始化 Gradle 骨架 + 本地依赖（sdk/amqp/slf4j）。
2. 实现 ConnectionManager 与 RabbitConnection（连接生命周期）。
3. 实现生产面板。
4. 实现消费面板 + 消息详情。
5. 装配 `RabbitMQToolFactory` 与三资源文件、logo.svg、plugin.xml。
6. 构建打包出工具 JAR，核对 JAR 根含三资源、内含第三方依赖。
7. 在宿主 IDE 2026.2 中「安装本地插件」装配并走查；用 dbx RabbitMQ（114.66.55.245:20070）做生产/消费闭环功能测试。
8. 清点测试痕迹（新建的 vhost/queue/exchange/消息/消费标签行），能清则清。

## 七、验收标准

- 工具 JAR 可被 Cool Request 2026.2 加载并显示图标、名称，面板可打开。
- 能对新连接的 RabbitMQ 建连接、发消息（direct/topic/fanout 各验一条）、订阅收消息、查看消息详情。
- 连接增删改选与输入持久化跨会话生效；关闭面板无连接/线程泄漏。
- 全部阻塞操作不卡 UI；异常返回用户可读信息。
