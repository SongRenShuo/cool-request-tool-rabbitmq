# RabbitMQ 小工具踩坑与经验沉淀

> 开发/走查过程中沉淀的坑与定例。配合 `docs/开发计划.md`（构建与功能说明）、`docs/UI走查计划.md`（走查清单）阅读。

## 一、构建链

- **必须用 IDEA 自带 jbr（JDK25）的 javac**：IDEA 2026.2 platform lib 类文件版本 v69，JDK17 编译直接报「类文件版本 69.0」。`--release 17` 输出兼容运行时。
- **classpath 用字面通配**（`$IDEA_LIB/*`），javac 自行展开；不要用 argfile——argfile 里通配与引号都不展开，报「无效的标记」。
- **git bash 跑 `java -cp` 带 `;` 分隔必须 `export MSYS2_ARG_CONV_EXCL="*"`**，否则 MSYS 路径转换吞掉 classpath 条目，编译能过但运行报 NoClassDefFoundError（极具迷惑性）。
- **test/manual 下的 .java 不会被任何构建自动编译**，回归 harness 前须先 `javac -d test/manual/classes` 再跑；旧的 .class 产物被清理后会报「找不到或无法加载主类」，是环境问题不是代码问题。
- **jbr 没有 javap**：查 jar 内类的方法签名，用 Python `zipfile` 读 class 文件 + 常量池正则（本仓已多次实证，比装 JDK 快）。

## 二、amqp-client 5.21 API 坑（编译器证伪过）

- **`ReturnListener` 回调参数是 `com.rabbitmq.client.Return`**，不是 `AMQP.Basic.Return`——用错直接编译失败。
- **`exchangeDeclarePassive` 返回 `AMQP.Exchange.DeclareOk`**，不是 boolean，不能当判断用。
- **406 PRECONDITION_FAILED 会关闭 channel**：任何「试探性声明再重试」的路线，每轮失败后必须 `connection.createChannel()` 换新通道，复用旧通道必挂。

## 三、406 声明冲突的完整认知（四轮修复的核心）

Producer 发送前 `exchangeDeclare(exchange, type, durable, autoDelete)` 与 broker 存量交换机属性不符即 406：

1. **冲突维度有三个：durable、autoDelete、type**，任何一个不等都触发 `inequivalent arg`。
2. 同 type 下 **durable×autoDelete 四组合逐值试探**（{F,T}/{T,T}/{F,F}/{T,F}），406 换通道试下一组合，命中即沿用服务端现状——能救属性冲突，救不了 type 冲突。
3. **type 不符时四组合救不了**（type 不在试探维度里，全 406）——正解是 **AUTO 档：不声明直接 publish，绝不自动创建**。这是默认档，对既有业务交换机（如 durable=true 的 dev_esign-BIZ-A）永远不会再 406。
4. 测试数据预建必须对齐插件声明口径：Producer 交换机按用户显式类型、Consumer 队列 `queueDeclare(durable=true)`；管理 API 预建的数据属性不符就会 406（假失败易误判为代码 bug）。

## 四、IntelliJ 平台（262）UI 坑

- **带 `project` 的 `EditorTextField` 构造器在 EDT 同步建 PSI document**，无读访问时硬抛 `RuntimeExceptionWithAttachments`。修法 = **无 project 构造 + `setNewDocumentAndFileType(FileType, Document)`**；`EditorEx` 上没有 `setFileType`（常量池核实过，别试）。
- **GridBagLayout 复用同一个 GridBagConstraints 必须逐组件递增 gridx**——同格叠放不报错、只静默互相遮挡（浏览面板 Peek next/Refresh 按钮不可见的真因）。排查手法：Producer/Consumer 面板正常而某面板按钮缺失，先数 gridx。

## 五、错误提示设计定例（AmqpErrors）

- **IOException.getMessage()==null 是常态**（vhost 错等场景），根因在 cause 链的 ShutdownSignalException 里；错误翻译必须下钻 cause（8 层封顶），并从 AMQP close 帧提取 `reply-text=` 作首行。
- 翻译三段式：reply-text 首行 + 可操作中文建议 + 类型/位置（3 帧栈）。任何出口禁止裸 null。
- 已知小瑕疵（不阻塞）：NO_ROUTE 退回的建议语未按交换机类型区分措辞；406 建议语固定说 durable 未解析出实际冲突参数名——均可从 reply-text 里解析改进。

## 六、消息语义定例

- **发布一律 `mandatory=true` + ReturnListener**（800ms 等待退回）：「Send OK」与「消息被 broker 退回（未路由到任何队列）」必须区分，否则 headers 绑定不匹配时假 OK，用户以为消息送达实际消失。
- **非法 Headers(Json) 必须发送前拦截**，`catch ignored` 静默吞会造成「界面 OK 消息实际裸发」。
- Browse 用 **basicGet 只读 peek + 尾部统一 basicNack requeue**，不消费不丢消息。

## 七、版本与发行约定

- tools-rep 全生态工具**恒为 1.0-SNAPSHOT 一版到底从不升版**（多数 jar 还是 template-1.0-SNAPSHOT-all.jar）；升级由 coolrequest.dev 商店后台 checksum/minVersion 字段管理，jar 名不变也能更新上架。
- 上架两步缺一不可：PR 进 `tools-rep/` + **作者在 coolrequest.dev 后台录入**（列表走后端 API 非目录扫描）。
- **凭据纪律**：测试 broker 凭据只能走命令行参数（harness 模式），任何硬编码凭据的 Smoke*.java 一律不进 PR。
